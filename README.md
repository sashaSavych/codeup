# CodeUp

Навчальний вебзастосунок **CodeUp** — частина магістерської кваліфікаційної роботи з теми методики навчання JavaScript у курсі «Інформатика» з використанням вільного ПЗ. У цьому каталозі ведеться розробка вихідного коду.

**Канонічні матеріали диплому** (узгоджувати зміри концепції там і тут):

- план застосунку, екрани, ролі, етапи: [`../app/app.txt`](../app/app.txt);
- стек технологій і хостинг: [`../app/stack.txt`](../app/stack.txt).

### Реалізований базовий стек (це репозиторій)

| Компонент | Примітка |
|-----------|-----------|
| Angular **21**, TypeScript | SPA, routing, префікс селекторів `cu-`, standalone-компоненти |
| PrimeNG **21.1.6** (community, MIT) | Не використовувати збірки **`-lts`**. Тема Aura (`@primeuix/themes`), `provideAnimationsAsync`; `@angular/cdk` узгоджено з Angular 21 |
| Tailwind CSS 3 | `preflight` вимкнено, щоб не конфліктувати зі стилями PrimeNG |
| `@angular/localize` | Підготовка до української локалізації |
| `monaco-editor`, `@supabase/supabase-js` | Залежності додано; підключення редактора й бекенду — наступні етапи |
| Jasmine / Karma | Як у шаблоні Angular CLI |

**Запуск локально:** з каталогу `codeup/` виконати `npm install`, потім `npm start`. Збірка: `npm run build`; тести: `npm test`. Конфігурація Supabase (не комітити ключі): скопіювати `src/environments/environment.development.example.ts` у `environment.development.ts` і заповнити **Project URL** та **Publishable** ключ (`sb_publishable_...`) з вкладки **Publishable and secret API keys** у Dashboard → Settings → API Keys (JWT **anon** з вкладки Legacy ще підтримується під час міграції). Для збереження профілю учня виконайте SQL з **`supabase/profiles.sql`** у Supabase → SQL Editor (таблиця `profiles` і RLS). Список тем і текст теорії зберігаються в таблиці **`topics`**: виконайте **`supabase/topics.sql`** (публічне читання для `anon` і `authenticated`, початкові дані з Markdown).

**Автентифікація:** маршрути `/signup`, `/login`, `/profile`. Після реєстрації, якщо сесія активна одразу (без обов’язкового підтвердження email), виконується перехід на `/profile`.

## Узгодження з теоретичними розділами (1.1–1.3, 2.1)

| Джерело | Вимога до ПЗ |
|--------|----------------|
| **1.1** | Відтворюваність сценарію уроку вдома й у класі (браузер, мінімальний старт); логіка «алгоритмізація → запис мовою → вебконтекст»; не замінює робочу програму — лише модуль JavaScript. |
| **1.2** | Компетентнісний, задачний і проєктний підхід; вправи на читання й трасування коду; поступове зняття підтримки (підказки → відкрите завдання); формувальне оцінювання — статуси вправ і рубрики, без «готового розв’язку для учня». |
| **1.3** | Вільне ПЗ і прозорі ліцензії залежностей; критерії для ЗЗСО (ліцензія, офлайн/онлайн, мова UI, безпека, приватність, дидактика, відтворюваність уроку); за можливості — WCAG. |
| **2.1** | Навігація за темами як у модулі (~7 блоків); у кожній темі «теорія → завдання → практикум»; статуси вправ узгоджені з формувальним оцінюванням; помилки й рефлексія — підказки й чат у межах політики чесності. |

## Зв’язок із навчальним модулем (2.1)

- Послідовність тем як у концепції модуля JavaScript (від мінімального прикладу до міні-продукту).
- Для кожної теми: **теорія → завдання → практикум**, єдиний стиль формулювань.
- Статуси вправ — за потреби узгодити з рубриками (наприклад: спроба / виконано / з підказкою / потребує доопрацювання).

**Потоки даних (коротко):**

- Тема → теорія / завдання → практикум → перевірка коду → статус вправи → за правилами бали й серія.
- Чат ШІ: ідентифікатор теми/вправи та обмежений контекст умови **без готового розв’язку**.
- Гейміфікація підкріплює регулярність і успіх; правила прозорі для учня й вчителя.

## Автентифікація та ролі

- Вхід з ролями **учень** і **вчитель** (бекенд, наприклад Supabase Auth, або узгоджено з ЗЗСО).
- **Учень:** модуль, теорія, завдання, практикум, гейміфікація, чат підтримки; прогрес і бали прив’язані до обліку.
- **Вчитель:** структура модуля, методичні матеріали; за потреби агрегована аналітика (етика й згода на дані); **не** «вирішити за учня» через ШІ від імені учня.
- **Guards:** неавторизованим — логін або обмежений демо-режим (за вибором).
- Сесія / токен / пароль — за стандартом постачальника автентифікації.

---

## Допомога на базі ШІ (чат)

- Чат у практикумі (і за потреби на завданні): підказки, пояснення помилок, нагадування з теорії **без видачі готового розв’язку** (промпти / модерація на бекенді).
- У запит: ідентифікатор теми/вправи, формулювання умови; мінімум персональних даних; логування — за політикою конфіденційності.
- Квоти, rate limit, повідомлення про помилки моделі; fallback — статичні підказки з модуля.

---

## Гейміфікація

- Бали за осмислену активність (успішні перевірки, перегляд теорії за правилами без «накрутки»).
- **Серія:** мінімальна щоденна активність → серія днів і бонус (формула в налаштуваннях).
- **Заморозка:** витрата бонусу, щоб зберегти серію в день без візиту; обмежити кількість заморозок за період.
- UI: бали, серія, доступні заморозки — видимі учню й вчителю.

## Функціонал і сторінки (UX)

**Передумови:** SPA або MPA в браузері; UI — **українська**; за можливості доступність (WCAG).

| Сторінка | Зміст |
|----------|--------|
| **Вхід / реєстрація** | Форма входу; роль учень/вчитель; відновлення доступу; короткі правила чату й гейміфікації. |
| **Головна / модуль** | Назва модуля; картки тем зі статусом; «Продовжити»; панель гейміфікації; для вчителя — методичні матеріали, експорт тем, опційно прогрес групи. |
| **Теорія** | Заголовок теми; «Що вивчаємо», ключові поняття; приклади коду з копіюванням; типові помилки; навігація до завдань/практики. |
| **Завдання** | Список вправ, індикатор виконання; перехід у практикум; вхід у чат з контекстом вправи. |
| **Практикум / редактор** | Умова вправи; редактор (підсвітка); Запустити / Очистити / Підказка; вивід (консоль або sandbox); чат ШІ; результат перевірки й нарахування балів. |
| **Довідник** (бажано) | Шпаргалка JS у межах модуля; пошук/якорі. |
| **Про застосунок / ліцензії** | Версія, автор; залежності з ліцензіями; постачальник API ШІ та умови даних у чаті. |

## Етапи розробки ПЗ

1. Аналіз вимог і змісту модуля (2.1); політики ролей, чату ШІ, гейміфікації; критерії 1.3.
2. Проєктування UI й сценаріїв уроку (учень / вчитель).
3. Реалізація ітераціями: каркас і автентифікація → теорія → завдання й практикум → чат ШІ → гейміфікація → доступність.
4. Внутрішнє тестування (завдання, безпека коду, чат, бали й заморозки).
5. Підготовка до пілоту в ЗЗСО.

Код у тексті диплому — мінімально; повні лістинги — у додатках або за погодженням з керівником (**репозиторій `codeup/`**).
